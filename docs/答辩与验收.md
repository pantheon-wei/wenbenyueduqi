# 答辩与验收

## 约 5 分钟功能演示

1. **0:00–0:40**：运行 `npm start`，打开 localhost:5173。介绍拾页的主题，使用初始《林间漫步》演示书。
2. **0:40–1:30**：点击导入，选择 `samples/导入演示.txt`；再用粘贴方式新增一份笔记。切换书籍、搜索书名、排序，并取消一次删除确认，随后确认删除笔记。
3. **1:30–2:30**：选回《林间漫步》，滚动到中段。把字号从 20 调到 26，展示段落保持；切换背景和自定义颜色，开启/关闭护眼模式，切换夜读主题。
4. **2:30–3:30**：打开目录跳到第五章，添加书签，滑动到其他位置，再点击书签回来。切换到另一本书再回来，并刷新页面，检查正文位置、书签和设置恢复。
5. **3:30–4:20**：按 F 进入专注，PageDown 翻页，Esc 退出。缩窄窗口展示手机书架和设置抽屉。
6. **4:20–5:00**：导出备份；删除演示导入书后恢复备份，展示书架和书签恢复。说明全部正文保存在浏览器本地，不上传。

## 约 10 分钟架构讲解

### 1. 架构与数据流（2 分钟）

```text
用户操作
  ↓
app.js（事件 → 内存 state → 局部渲染）
  ├── core.js（解码、解析、校验、阅读位置算法）
  ├── storage.js（IndexedDB 事务）
  └── styles.css（CSS 变量决定排版与主题）

Node server.mjs 只提供静态文件，不接收书籍正文。
```

`state.books` 是以内容摘要为键的 Map；`currentId` 决定当前书；`settings` 是全局阅读偏好；`parsed` 与 `tops` 是当前书的派生数据，可从正文和 DOM 重新计算，不作为永久数据存储。

### 2. 导入与书架（2 分钟）

File API 读取 ArrayBuffer；TextDecoder 按所选编码解码，自动模式优先 BOM/UTF-8，失败再尝试 GB18030。规范化换行和 BOM，检查空内容和大小。正文 SHA-256 用于内容去重，避免重命名文件导致重复导入。同内容只保留原书与原进度。

书架新增先完成数据库写入，再修改内存和页面；避免存储失败后界面仍显示“成功”。删除需要确认，同时删掉正文和状态。导入文本通过 `textContent` 输出，不作为 HTML 执行，因此 `<script>` 只会显示为文字。

### 3. 本地存储（2 分钟）

数据库有三个 object store：

| Store | 主键 | 内容 |
| --- | --- | --- |
| books | id | 书名、作者标记、正文、加入时间 |
| states | id | 段落位置、百分比、书签、最后阅读时间、阅读秒数 |
| meta | key | 当前书、全局设置、初始化标记 |

正文通常较大且很少变化，进度很小且高频更新，因此分开存。滚动用 250 ms 防抖降低写入频率，串行写入队列避免旧状态后写覆盖新状态。切书先保存旧书，刷新/离开时写一个同步的小恢复点，下一次打开仍从数据库加载全部正文。

IndexedDB 是正式数据库，localStorage 只存最后一本书的小型状态恢复点，不用于保存全文。浏览器空间不足会提示失败，不能保证用户清理数据后仍保留书架，需定期备份。

### 4. 阅读位置与主题（2 分钟）

仅保存 `scrollTop`，字号变化后会错位；仅保存百分比，长段落高度变化后也可能偏移。这里记录 `index + fraction + progress`：段落索引、在当前段落到下一段落间的比例、整体滚动百分比。重新排版后计算段落的新坐标，恢复同一索引和比例；末尾或索引失效时使用百分比兜底。

滚动时缓存段落坐标，用二分查找定位当前段落。字号/行距改变、专注模式和容器尺寸改变后重新测量。动画帧恢复期间设立 `restoring` 标记，避免程序滚动被误当成用户阅读并保存错误位置。

CSS 变量控制字号、行距、背景、正文颜色、字体。护眼模式作为独立设置覆盖背景，关闭后使用原主题。自定义背景通过相对亮度选择深色/浅色文字。只允许预设主题和 6 位十六进制颜色进入样式。

### 5. 选型、创新与改进（2 分钟）

| 选择 | 原因 | 代价 / 后续方向 |
| --- | --- | --- |
| 原生 ES Modules | 不依赖构建安装，现场容易启动、解释和修改 | 功能继续增长后可拆分渲染与控制模块 |
| IndexedDB | 异步、大文本支持优于只用 localStorage | 浏览器来源隔离，不等同云同步 |
| Node 内置服务器 | 无依赖，跨平台运行，静态部署简单 | 在线部署改用 HTTPS 静态托管 |
| 正文按纯文本呈现 | 安全、符合 TXT 阅读需求 | 不支持 EPUB/PDF 或复杂 Markdown 排版 |
| 段落锚点 | 排版变化仍能继续读同一段落 | 同一很长段落内不是精确字符锚点 |
| 一次渲染当前书 | 实现简单，适合考核和普通文本 | 10 MB / 40,000 段上限；更大书可用虚拟列表 |

创新点：以“慢读”作为视觉和交互主题，结合段落位置保持、专注模式、原创示例、目录、书签和跨浏览器手动备份迁移。护眼模式仅调整配色，不声称医学效果。

## 完整手动验收清单

- [ ] 初次打开自动出现示例；删空全部书后刷新仍保持空书架，可点击试读重新添加。
- [ ] UTF-8 / GBK / UTF-16 文本导入；空文件、错误类型、过大文件得到提示。
- [ ] 多本文件导入；同正文重复导入不丢失原进度；特殊字符书名和正文仅显示文本。
- [ ] 粘贴新增；空标题和空正文被拒绝；书架搜索和三种排序可用。
- [ ] 删书取消不改变数据；删当前书、删最后一本后状态正确；原始文件仍存在。
- [ ] 字号 14–36、行距 1.4–2.6、字体切换；改变排版后段落没有明显跳走。
- [ ] 四种主题、自定义背景、护眼开关、默认重置；刷新后设置恢复。
- [ ] 进度条跳到 0%、中段和 100%；切书、刷新、关闭再打开恢复阅读位置。
- [ ] 目录跳转；添加、跳转、删除书签；刷新后书签仍在。
- [ ] 备份后删除书籍再恢复；损坏 JSON、错误格式备份不会清空原书架。
- [ ] 手机宽度可打开书架与设置，正文无需横向滚动；桌面侧栏与设置可见。
- [ ] F、B、Esc、PageUp/PageDown 可用；输入文本时快捷键不误触发。
- [ ] 数据存储失败时提示，不显示已成功保存。

## 适合现场演示的修改

将“剩余阅读时间”的估算速度从每分钟 400 字改成 500 字：在 `src/app.js` 的书籍摘要和 `updateProgress` 中修改相关常数与提示文字，刷新验证。进一步改进可把它提升为 `core.js` 的统一常量，以避免两个位置不一致。解释这次改动涉及派生展示，不改变原文或阅读进度的数据模型。
