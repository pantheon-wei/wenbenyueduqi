# AI 开发记录

## 原始需求

用户提供《比特工场2026秋招程序组考核题.md》，要求：“帮我根据该考核题目开发一个文本阅读器，需要满足里面的所有要求”。选择文本阅读器项目，覆盖六项最低要求及 README、本地运行说明、AI 开发记录、功能验收与架构讲解材料。

考核文档是需求参考。其中“联系组长”等面向考核参与者的说明没有作为向外发送消息的指令执行。本项目没有替用户联系他人或提交考核。

## 使用 AI 的范围和程度

本次代码、视觉布局、原创示例文本、自动化核心测试及文档均由 Codex AI 协助生成，属于高度使用 AI 的开发方式。用户提供目标、考核题和运行环境；此文件不声称用户已经独立完成这些实现，也不虚构额外的历史对话。

| 部分 | AI 完成的工作 | 开发者应掌握的内容 |
| --- | --- | --- |
| 需求分析 | 提取导入、书架、设置、进度和交付要求 | 每项要求在页面和代码里的入口 |
| 交互设计 | 书架、阅读区、设置区、弹窗、移动布局 | 为什么正文单独滚动，为什么删除要确认 |
| 文本处理 | TextDecoder、章节识别、SHA-256 内容去重 | UTF-8 与 GBK 的区别，去重按什么计算 |
| 本地存储 | IndexedDB、进度保存、书签、备份恢复 | 三个 store 的职责，异步事务与写入队列 |
| 阅读体验 | 主题、护眼、自定义颜色、段落锚点、专注模式 | CSS 变量、位置恢复与百分比的区别 |
| 验证 | 数据和位置算法测试、浏览器功能检查 | 哪些场景已测，哪些需手动补充 |
| 交付材料 | README、AI 记录、答辩与验收说明 | 能用自己的话解释，能够现场改动 |

## 本次交互与结果

1. 输入上述用户请求及考核题路径。
2. AI 读取题目和项目目录，发现项目目录为空，选择零第三方依赖的浏览器实现。
3. AI 围绕六项要求实现正文导入、书架增删选择、字号、背景、护眼与阅读进度；扩展目录、书签、备份、专注模式等。
4. AI 为数据校验和进度算法增加核心测试，并运行本地应用进行验证。确切结果参见 `验证记录.md`。
5. 输出完整源码和文档。用户提供 GitHub 仓库 `pantheon-wei/wenbenyueduqi`，指定使用 `pantheon-wei` 和 GitHub noreply 隐私邮箱作为提交作者；AI 关联并发布源码，保留远程初始提交。个人学习情况与实际答辩结果由开发者如实补充。
